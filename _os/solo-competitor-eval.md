# solo-agent-kit — 针对性评估（FDE 综合能力 / 竞品对比 / 能力到达率 / 商业化）

> 评估对象：`本仓库根目录`（当前 HEAD `c06e168`，10 核心原子）
> 参考文档：`_os/solo-fde-atomic-architecture.md`、`_os/solo-fde-linkage-deepen.md`、`_os/fde-latest-tech-deepdive.md`
> 评估方式：**实测代码而非读文档**（跑 `pytest tests/` 全量 + 逐能力 `run_capability` 真实数据验证 + 组装链 `run_flow` 端到端）

## 2. 竞品对比（FDE 现场交付 / 工业 AI 落地工具）

### 2.1 对标竞品类别

| 竞品类别 | 代表 | 核心能力 | 强项 | 弱项 |
|---|---|---|---|---|
| 通用 Agent 框架 | LangChain/CrewAI | LLM 编排 | 生态大、模型多 | 不落地工业现场、无本体/无零依赖、甲方难自持 |
| 工业本体平台 | 西门子/施耐德行业知识图谱平台 | 本体+语义 | 图谱强 | 重、闭源、绑定平台、贵、数据出厂 |
| 物联网监测平台 | 树根/海康 | 设备接入+看板 | 实采协议全 | 通用监测，无 FDE 交付闭环、无诊断/本体 |
| SaaS MES | 主流 MES | 生产执行 | 业务覆盖广 | 重实施、数据上云、非可嵌入底座 |
| Palantir Foundry | Palantir | 数据集成+本体 | 企业级本体强 | 超重、超贵、闭源、非一人公司可用 |
| **solo（本次）** | — | 监测+诊断+本体+交付+记忆 | 零依赖/离线/本体优先/可嵌入/可自持/交付闭环 | 协议实采浅、写作未原子化、RAG 雏形 |

### 2.2 solo 差异化定位

**solo 不是"又一个平台"，是"可被甲方自持的 FDE 开源算法底座 + 交付闭环"。** 差异化在四件事：

1. **零依赖 + 离线 + 数据不出厂**（唯一纯标准库全栈，甲方敢用、敢自持、敢离线）——对标所有重平台，这是独占优势。
2. **本体优先**（确定性问答，先建语义再检索）——对标通用 Agent 框架的纯 LLM 检索。
3. **交付验收闭环**（需求→SRS→验收→勾稽→交付包→签收）——对标 MES/监测平台的"只有看板没有交付"。
4. **开源原子 + 闭源编排**（Apache-2.0 算法全开源，交付增值闭源）——建立信任 + 可持续商业。

### 3.3 到达率结论

## 4. 商业化评估（卖结果 / 定价 / Open-Core / 甲方价值锚定）

### 4.1 卖结果定价（量化价值锚点）

| 价值锚点 | 数值 | 用途 |
|---|---|---|
| 非计划停机损失 | 12.6%（IDC 制造业均值） | 停机损失量化基线 |
| 预测性维护停机下降 | ↓63.8% | 卖"预测维护"结果 |
| 动态阈值误报率下降 | ↓61%（MAD 稳健基线 vs 静态阈值） | 卖"少误报"结果 |
| 交付验收闭环 | 需求→SRS→验收→勾稽→签收 全自动 | 卖"可签收交付"结果 |

**FDE 人天定价**：普通 3-6k / 高级 6-12k（对齐文档）。
**Open-Core 商业模式**：开源算法（获客/信任/甲方自持）+ 闭源 `deliver-accept` 编排增值（订阅/买断）→ 三阶段收入（服务→软件→平台）。

### 4.2 甲方价值锚定

solo 卖给甲方的不是"工具"，是**"可自持的 AI 底座 + 交付闭环结果"**：
1. **数据不出厂 + 零依赖** → 甲方敢用（合规/安全/自主）。
2. **开源可自持** → 甲方不被平台锁定，可迭代维护。
3. **交付验收闭环** → 从"看板"升级到"可签收的交付包"，乙方可对验收负责、甲方可验收。
4. **本体优先** → 知识资产沉淀，不只问答。

### 4.3 行业方案对标 & 商业化短板

| 对标 | solo 位置 | 短板 |
|---|---|---|
| 通用 Agent 框架 | 差异化：落地工业+零依赖 | 生态小 |
| 工业本体平台 | 差异化：轻+可自持 | 本体推理深 |
| 物联网平台 | 差异化：交付闭环 | **协议实采浅**（OPC-UA/Modbus 不可用，卖监测场景会被卡） |
| SaaS MES | 差异化：可嵌入底座 | 业务覆盖窄 |

**商业化最大障碍不是产品，是「测试不全绿 + 写作未原子化」**：甲方签收前必然跑测试，21 条红测会直接摧毁信任。且协议实采（OPC-UA/Modbus）是工业现场卖点的硬门槛。

## 5. 结论

### 5.1 能力分

| 项 | 分值 |
|---|---|
| FDE 综合能力分 | **6.8 / 10** |
| 竞品对比整体分 | **7.3 / 10**（一人公司 FDE 细分赛道领先） |
| 能力到达率 | **约 70%**（核心闭环可用，25% 雏形，5% 断链） |
| 商业化成熟度 | 中（定价/Open-Core/价值锚定清晰；测试红 + 协议浅是硬伤） |

### 5.2 竞品定位

**solo = "一人公司/乙方 FDE 的零依赖离线开源底座 + 可签收交付闭环"。** 差异化独占在"零依赖离线可自持 + 本体优先 + 交付验收闭环"，在细分赛道综合领先通用 Agent 框架（7.3 vs 5.3）、工业本体平台（5.9）、物联网平台（5.7）、SaaS MES（5.6）。最大护城河是**纯标准库 + 数据不出厂 + 开源可自持**。

### 5.3 能力到达率

核心交付闭环（监测→诊断→决策→工单→知识库→交付验收）**真实可用**；RUL/协议实采/RAG/写作原子化/自进化为雏形；**测试与文档断链**（21 红 + 15vs10 原子）是当前最刺眼的短板。

### 5.4 优化优先级

| 优先级 | 项 | 说明 |
|---|---|---|
| **P0** | **修复 21 条红测 + 文档对齐 10 原子** | 测试全绿是签收与开源信任的前提；删除/改写过期 linkage-deepen 测试，文档 15→10 原子对齐 |
| **P0** | **写作原子落盘**（write-qa/write-evidence）并接入交付链 | 写作是交付报告的一环，不原子化 = 交付链缺一块 |
