## 二、进化顺序（按依赖 + 价值排优先级）

### 阶段一：skill 代码骨架（地基，0.8.x）
**为什么先**：skill 是"经验沉淀"的最高层，把自然语言规则升级为**可执行代码骨架**，才能让"进化"有载体（VISION §22 吸收 Burin"代码即记忆"）。

**做什么**：
1. skill.py 的 `add` 支持 `type="skeleton"`：steps 存代码骨架而非纯文本
2. `run_skill(name, context)` 执行骨架（调用 code_agent 生成/复用原子库）
3. 浅层文本规则 → 中层代码骨架，自动升级路径

**验证**：skill 存一个代码骨架，`run_skill` 能执行产出结果。

### 阶段二：AHE 可证伪进化 harness（闭环，0.9.x）
**为什么第二**：task.py 已有 predict/verify_prediction（可证伪预期）和 gate（决策门），只差**把它们串成自动循环**。这是"可成长"的引擎。

**做什么**：
1. 新建 `solo/harness.py`：`run_with_evolution(task, skill_dir)`
   - 执行任务 → 记录可证伪预期(predict) → 运行后验证(verify_prediction)
   - 预期失败 → 提炼教训 → 写入 skill（浅层或代码骨架）
   - 形成"行动→预测→验证→沉淀"闭环
2. 复用 agent.run + task.predict/verify

**验证**：跑一个会失败的任务，确认教训被提炼并沉淀进 skill。

### 阶段三：主动思考/会话间内省（自主性，1.0 前）
**为什么第三**：依赖 AHE 闭环先存在（内省是在闭环之上反思）。吸收 zeroclaw/ACL2026 记忆三阶段的"主动探索"。

**做什么**：
1. 空闲钩子：会话间检查待处理 skill/未验证预期
2. 主动检索记忆发现缺口，补全知识
3. 长任务断点续跑时，主动总结进度

### 阶段四：工程完备（1.0 发布门槛）
- workflows/ 编排（YAML 定义多步流程）
- gateway/ 消息平台（对接 DingTalk/Web 前端）
- 记忆 API 化 + 多源导入（吸收 mem0/khoj）

### 阶段五：生态（1.0 后）
- 案例库（本体优先 + 中文工业落地的 best practice）
- 文档完善 + 社区

## 三、优先级矩阵

| 阶段 | 事项 | 价值 | 依赖 | 紧迫度 |
|---|---|---|---|---|
| 一 | skill 代码骨架 | 进化载体 | 无 | 🔴 高 |
| 二 | AHE harness 闭环 | 进化引擎 | 阶段一 | 🔴 高 |
| 三 | 主动思考 | 自主性 | 阶段二 | 🟠 中高 |
| 四 | workflows/gateway | 工程完备 | 阶段一 | 🟡 中 |
| 五 | 生态案例 | 影响力 | 全部 | 🟡 中 |

**关键路径**：skill骨架 → AHE闭环 → 主动思考（这是"工具长成 Agent"的本质路径）

---

## 四、红线（不破坏轻量定位）

- 每个阶段都过"零依赖红线"——吸收的是**设计思想**（骨架/闭环/内省），不是功能堆砌
- 不引重依赖（不引 LangChain/deer-flow 式框架）
- 不追"通用 Agent"（滑向 nanobot 定位=输）
- 守住"本体优先 + 方法论完整 + 一人公司"交叉点
